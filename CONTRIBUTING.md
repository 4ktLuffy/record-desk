# Contributing

Use synthetic fixtures. Never submit real receipts, credentials, local databases, or customer records. Run the tests and JavaScript syntax check from the README before opening a pull request.

Describe the problem, behavior change, and validation. Preserve source values, make normalization explicit, keep ambiguous matches visible, and avoid provider calls in automated tests. Changes to matching semantics need examples covering duplicates, missing values, and conflicting records.

Please discuss large features in an issue before implementation. The current scope is a local single-user tool; do not describe it as production-ready hosting software.
